# Edge function rules

- All AI calls go through the Lovable AI Gateway on its current default chat model with reasoning enabled; function tools are sent through the Responses endpoint via the shared `supabase/functions/_shared/aiResponses.ts` helper (stateless: every call resends its input with `store:false`), because the gateway's chat-completions endpoint serves text generation only.
- The live interview chat (ai-interview-chat, conversation turns only) asks the gateway for the lowest reasoning effort it accepts (none, then minimal, then low) because a person waits for every reply, and its first message is a fixed greeting sent without calling the model; evaluation, co-pilot and all other AI calls keep reasoning_effort low.
- Administrator notification emails use credential-free pg_net event callbacks and service-only atomic claims with bounded retries and managed idempotency; only stored notification content and the administrator's own address may be sent, without new queues or schedules.
- Send payout approval emails from the dedicated authenticated payout notification function after the existing status RPC succeeds, deriving recipient, money and date server-side and deduplicating by payout ID; email failures must not undo financial actions.
- Scheduled consultant profile reminders are credential-free like administrator notification emails: the POST entry point carries no secret, safety lives in the service-only claim RPC plus a 30-minute repeat-call guard, and responses contain counts only.
- Assignment request reminders follow the same credential-free pattern with a 4-minute sweep guard (below the 5-minute schedule so Critical reminders are not held back); timings and due rules live in `_shared/assignmentPolicy.ts`, mirrored by the claim RPC, so popup, e-mails, client card and tests agree.
- Consultant responsiveness (Feature M) is computed only in the database from arrival-time events (availability checked when a request arrives); `_shared/responsiveness.ts` mirrors the rules for display, ranking and tests, and the responsiveness-run sweep follows the same credential-free pattern with an 8-minute guard, so cards, ratings and ranking never compute official statistics in the browser.
- Consultant Service Policy notices (consultant-policy-run) follow the same credential-free sweep pattern with the shared 30-minute guard; acknowledgement state and grace rules live only in the database (mirrored by `src/lib/consultantPolicy.ts` for display), so pop-up, banners, e-mails and restrictions agree.
- Admin user management (admin-manage-user, admin-send-invitation) checks the caller with `admin_can` (falling back to the admin / super admin role until the prepared SQL is applied), requires a reason for sensitive actions, rate limits per admin and records every change through `um_record_state` with actor, target, before, after and reason; bulk runs are capped at 200 with a dry run first.
