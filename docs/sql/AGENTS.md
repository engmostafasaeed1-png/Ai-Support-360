# Prepared SQL rules

- Prepared SQL files that redefine shared gate functions (hidden_consultant_ids, critical_alert_targets, and the BRD approval hooks in team_gates/team_next_step/tt_facts/tt_timeline/brd_role_for) carry one identical combined body that probes optional helpers with to_regprocedure or calls hook functions whose no-op stubs the home file creates only while missing, checked by a test, so files can be applied in any order without dropping another feature's rule.
- Consultant profile submission (Feature V) is set only by submit_consultant_profile (guard trigger on consultants.profile_submitted_at) using consultant_submission_missing = consultant_missing_fields + hard-required fields + policy for new registrations; the browser only displays that list, so the gate cannot be bypassed and follows admin rule changes.
- Feature X name privacy: consultant names for another person go through consultant_name_for(consultant, viewer) (internal, recipient for notifications) or consultant_public_name (browser); stored notification texts use the context-free team_consultant_name (public format), so later NDA changes never leave a full name in old texts.
- Feature Z referral reward lines are written only by referral_create_reward at the payout-release event (payouts trigger + nightly catch-up, row locks, unique line per payout), stay pending for the hold period and mature in the nightly job; referral payouts are ordinary payouts rows with reference 'referral:%' that the reward code skips, so the normal payout run, bank details and due dates apply unchanged.
- interview_answers.question_source is protected by column privileges (signed-in users get every other column; admins read it through admin_interview_question_sources), so app screens must select named columns from interview_answers, never `*`.
- guard_ticket_context and consultant_missing_fields carry their newest body in consultant-roles.sql (help_roles key, role-aware required fields); re-applying matching.sql or support-agreements.sql after it would drop that, so copy the newest body into any later redefinition.
- consultant_achievements is read only with named columns (evidence_path and review fields are not granted; owners/admins use my_achievements/admin_achievements) and written only by the my_achievement_*/admin_achievement_review functions; consultant_completion's newest body (with the Success stories item) is in consultant-achievements.sql.
